# AoIP-Scope ユーザーマニュアル (Japanese Version)

AoIP-Scope は、ネットワーク上の AES67 や ST 2110-30/31 などの Audio over IP (AoIP) ストリームをリアルタイムでキャプチャし、PTP同期の安定性、パケットロス、およびジッターを詳細に解析・診断するためのプロフェッショナルなコマンドライン (CLI) ツールです。

---

## 1. 動作環境と前提条件

本ツールを正しく動作させるためには、以下の環境が必要です。

- **対応OS**: Windows 10 / 11 (64-bit)
- **キャプチャドライバー**: **Npcap** (または WinPcap) のインストールが必須です。
  - *注意*: Npcap がインストールされていない場合、ネットワークインターフェースの取得（`ifaces`）やライブキャプチャ（`record`）を行うことができません。
  - Npcap は公式サイト等から事前にインストールを完了させてください。
- **実行権限**: ネットワークパケットを直接キャプチャする（`record`）には、**管理者権限（Administrator）**での実行が必要です。コマンドプロンプトや PowerShell を「管理者として実行」で起動してください。
  - *注意*: オフライン PCAP ファイルの解析（`analyze`）のみを行う場合は、管理者権限や Npcap のインストールは不要です。

---

## 2. インストール

1. 配布された ZIP ファイル (`AoIP-Scope_v0.9.5.zip`) を任意のフォルダに展開します。
2. 展開されたフォルダ内の `AoIP-Scope.exe` が実行ファイルとなります。

---

## 3. 基本的な使い方とコマンド

AoIP-Scope は以下の3つの主要なサブコマンドを提供します。

1. **`analyze`**: PCAP/PCAPNG ファイルを読み込み、ストリームの健全性診断、PTP同期状態の解析、および音声抽出を行います。
2. **`record`**: ネットワーク上の AoIP パケットをキャプチャし、PCAPNG ファイルに保存します。
3. **`ifaces`**: 利用可能なネットワークインターフェース一覧を表示します。

---

### 3.1 `analyze` コマンド
取得した PCAP/PCAPNG ファイルを詳細に解析します。オフラインでの解析やデコード作業には、Npcapのインストールや管理者権限は不要です。
*注意: 後方互換性のため、サブコマンド `analyze` を省略してファイル名を指定するだけでも解析を実行できます。*

**主要な引数:**
- `pcap` : 解析対象の PCAP/PCAPNG ファイルのパス。
- `--list` : ストリームとデバイスの一覧表示のみを行い、詳細解析やデコードを行わずに即時終了します。
- `--ssrc` : 音声抽出または詳細解析を行う対象の SSRC（16進数、例: `0x12345678`）。
- `--out` : 抽出した音声を保存する WAV ファイル名。
- `--mono` : ステレオなどのマルチチャンネルストリームから、特定の1つのチャンネルのみをモノラル WAV として抽出する場合のチャンネル番号 (1から始まる番号)。
- `--ch` : 特定の複数チャンネルを指定してWAVとして抽出する場合のチャンネルリスト (カンマ区切り、例: `3,4` 指定で3chと4chをステレオWAVとして一括抽出可能)。
- `--report` : 解析結果の診断レポート（JSON形式）を自動生成します。

**使用例 (全体のスキャンとサマリー表示):**
```powershell
.\aoip_scope.exe analyze ./raw_capture.pcapng
```

**使用例 (ストリーム一覧の簡易表示):**
```powershell
.\aoip_scope.exe analyze ./raw_capture.pcapng --list
```

**使用例 (特定の SSRC の音声を抽出し、WAV ファイルとして保存):**
```powershell
.\aoip_scope.exe analyze ./raw_capture.pcapng --ssrc 0x4B3D2A1C --out ./extracted_audio.wav
```

**使用例 (チャンネル1のみをモノラル音声として抽出):**
```powershell
.\AoIP-Scope.exe analyze ./raw_capture.pcapng --ssrc 0x4B3D2A1C --mono 1 --out ./extracted_ch1.wav
```

**使用例 (チャンネル3と4をステレオWAVとして一括抽出):**
```powershell
.\AoIP-Scope.exe analyze ./raw_capture.pcapng --ssrc 0x4B3D2A1C --ch 3,4 --out ./stereo_34.wav
```
*※3ch, 4ch, 5chを抽出して3chのWAVにする場合は `--ch 3,4,5` のように任意のチャンネルをペアリングして抽出可能です。*

**使用例 (詳細な JSON 診断レポートを生成する):**
```powershell
.\aoip_scope.exe analyze ./raw_capture.pcapng --report
```
*診断レポートは、実行したディレクトリ内に `report_YYYYMMDD_HHMMSS.json` として自動保存されます。*

---

### 3.2 `record` コマンド
指定したネットワークインターフェースから AoIP マルチキャストストリームなどのパケットをリアルタイムでキャプチャし、ファイルに書き出します。
*注意: このコマンドの実行には、Npcapのインストールおよび管理者権限（Administrator）が必要です。*

**主要な引数:**
- `-i`, `--interface` : キャプチャを行う NIC のインデックス（1から始まる番号）または名前。
- `-o`, `--out` : 出力ファイル名（デフォルト: `capture.pcapng`）。
- `-m`, `--mode` : キャプチャモード。`mirror` (受動的なミラーポート監視) または `join` (能動的な IGMP 加入リクエスト) から選択します（デフォルト: `mirror`）。
- `--ip` : `join` モード時に加入するマルチキャスト IP アドレス（例: `239.69.100.1`）。
- `-t`, `--duration` : キャプチャを行う時間（秒単位）。指定しない場合は `Ctrl+C` で終了するまでキャプチャし続けます。

**使用例 (ミラーポートからの受動キャプチャ - 10秒間):**
```powershell
.\aoip_scope.exe record -i 1 -o ./raw_capture.pcapng -m mirror -t 10
```

**使用例 (特定のマルチキャストグループに IGMP 加入してアクティブキャプチャ - 5秒間):**
```powershell
.\aoip_scope.exe record -i 1 -o ./stream_capture.pcapng -m join --ip 239.69.100.1 -t 5
```

---

### 3.3 `ifaces` コマンド
利用可能なネットワークカード（NIC）の一覧、IPアドレス、MACアドレスを表示します。`record` コマンドで指定するインターフェースの「インデックス（番号）」や「名前」を確認するために使用します。
*注意: このコマンドの実行には、Npcapのインストールが必要です。*

**使用例:**
```powershell
.\AoIP-Scope.exe ifaces
```

### 3.4 Windows ポータブル用利便性向上機能

本ツールには、非エンジニアや一般のオペレーターの方でも直感的に Windows エクスプローラー上でポータブルツールとして利用できるよう、以下のインテリジェントな支援機能が搭載されています。

1. **コマンドプロンプトの自動リサイズ機能**:
   - ツールが Windows 環境で実行されると、起動した瞬間にコマンドプロンプトのウィンドウサイズが自動的に「横140桁・縦45行」に拡張されます。これにより、追加された Bandwidth カラムや IP アドレス、Format などの高密度なネットワーク・音響情報が、画面幅不足によって `...` に省略されることなく、完璧な横一列の美しいレイアウトでフル表示されます。
2. **ダブルクリックおよびドラッグ＆ドロップ時の「即時終了（画面閉じ）」防止機能**:
   - コマンドラインツールは、ダブルクリックで起動したり、ファイルをアイコンにドロップして実行した際、処理完了時に画面が勝手に一瞬で閉じてしまうのが一般的です。
   - AoIP-Scope は起動方法を判定し、**直接起動（ダブルクリック、またはPCAPファイルをアイコンに直接ドラッグ＆ドロップして起動）された場合のみ**、処理完了時に自動的に閉じず、以下の英語待機プロンプトを表示して停止します。
     ```text
     ==================================================
     Press [Enter] to exit...
     ```
   - ユーザーが `Enter` キーを押すまでウィンドウが生存するため、落ち着いて画面上の解析テーブルの内容を確認可能です。
   - ※コマンドプロンプト等から通常のCLI自動化スクリプトで呼び出された場合は、この入力待機は一切発生せず即時終了します。

## 4. トラブルシューティング

### 4.1 キャプチャが開始できない、またはインターフェース一覧が空である
- **原因 1**: `Npcap` がインストールされていません。
  - *対策*: Npcap をインストールしてください。インストール時のオプションで「WinPcap互換APIサポート」にチェックを入れることを推奨します。
- **原因 2**: 管理者権限でコマンドラインを起動していません。
  - *対策*: コマンドプロンプトや PowerShell を「管理者として実行」で起動し直してください。

### 4.2 解析を実行しても「No active RTP streams found」と表示される
- **原因 1**: キャプチャしたインターフェースに実際の AoIP オーディオトラフィックが流れていません。
  - *対策*: `ifaces` コマンドで接続している正しいネットワークカードの番号を指定しているか再確認してください。また、ネットワークスイッチ側でポートミラーリング（SPAN）が正しく設定されているか確認してください。
- **原因 2**: 能動的にストリームを要求する必要があるネットワーク環境です。
  - *対策*: `record` コマンドの `-m join` モードを使用し、受信したいストリームのマルチキャスト IP アドレス（`--ip`）を正確に指定してキャプチャを実行してください。

### 4.3 音声抽出（WAV保存）が失敗する、または「SKIP: Not a raw PCM stream」となる
- **原因**: 抽出対象のストリームが L24 または L16 以外の音声エンコーディング形式、あるいは規定の RTP ペイロードタイプ（96〜127）を使用していません。
  - *対策*: 解析結果の「Format」欄を確認し、AES67 / Dante 準拠 of 24ビット PCM (L24) または 16ビット PCM (L16) ストリームであることを確認してください。

## 5. 音声抽出WAVのファイルサイズ計算と実例 (Advanced Reference)

本ツールで抽出される WAV 音声ファイルのサイズは、AoIP 規格固有のパケットパラメータ（パケット送信周期: `ptime`）およびキャプチャ時間（総パケット数）と数学的に完全に連動しています。

WAV ファイルサイズ（バイト単位）は、以下の計算式で一意に算出されます：

$$\text{ファイルサイズ} = (\text{総フレーム数} \times \text{チャンネル数} \times \text{ビット深度のバイト数}) + 44 \text{ バイト (WAVヘッダー)}$$
* ※ 24ビット（L24）の場合は `1サンプルあたり3バイト`、16ビット（L16）の場合は `2バイト`。
* ※ 総フレーム数は $\text{パケット数} \times \text{1パケットあたりのサンプル数}$ で決まります。

以下は、同一のキャプチャファイル（PCAPNG）から異なるストリームを抽出した際の実例と内訳です。

### 実例 1: Dante マルチキャスト (AES67) ストリームの抽出例
* **ファイル名**: `extract_02CCFD32.wav`
* **ストリームパラメータ**: 2ch ステレオ / L24 (24-bit PCM) / 48000 Hz
* **送信周期 (ptime)**: **1.0 ms**（1パケットあたり **48 サンプル**）
* **キャプチャされた総パケット数**: 40,137 パケット
* **総フレーム数の計算**:
  $$40,137\text{ パケット} \times 48\text{ サンプル} = 1,926,576\text{ フレーム}$$
* **収録時間 (秒)**:
  $$1,926,576 \div 48,000\text{Hz} = \mathbf{40.137\text{ 秒}}$$
* **WAVファイルサイズの計算**:
  $$1,926,576 \times 2\text{ch} \times 3\text{バイト} + 44\text{バイト} = \mathbf{11,559,500\text{ バイト}}$$

### 実例 2: Dante ユニキャスト ストリームの抽出例
* **ファイル名**: `extract_DA434761.wav`
* **ストリームパラメータ**: 2ch ステレオ / L24 (24-bit PCM) / 48000 Hz
* **送信周期 (ptime)**: **0.333 ms**（1パケットあたり **16 サンプル**）
* **キャプチャされた総パケット数**: 111,945 パケット
* **総フレーム数の計算**:
  $$111,945\text{ パケット} \times 16\text{ サンプル} = 1,791,120\text{ フレーム}$$
* **収録時間 (秒)**:
  $$1,791,120 \div 48,000\text{Hz} = \mathbf{37.315\text{ 秒}}$$
* **WAVファイルサイズの計算**:
  $$1,791,120 \times 2\text{ch} \times 3\text{バイト} + 44\text{バイト} = \mathbf{10,746,764\text{ バイト}}$$

### 考察とポイント
1. **パケット送信周期（ptime）の影響**:
   Dante ユニキャスト（0.333ms）はマルチキャスト（1.0ms）に比べ約3倍高頻度でパケットを送出するため、パケット総数は非常に多くなりますが、1パケットあたりのデータサイズ（サンプル数）は3分に1になります。
2. **キャプチャ時間の差**:
   キャプチャ開始・停止タイミングのズレにより、ユニキャストの収録時間（37.315秒）がマルチキャスト（40.137秒）に比べて約2.8秒短くなっているため、ファイルサイズには約 812 KB の差が生じています。

このように、AoIP-Scopeはネットワーク上の生データを寸分違わず完全に復元するため、サイズの違いはストリームごとの規格特性および受信時間帯の違いを正確に反映したものとなります。
